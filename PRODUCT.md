# Product

## Register

product

## Users

MDX is for people writing and maintaining local Markdown workspaces on a desktop: developers, technical writers, researchers, and agent-assisted note takers who want direct control over folders and files. They are usually in a focused editing workflow, switching between the file tree, open tabs, document outline, and automation commands.

## Product Purpose

MDX provides a desktop-first Markdown workspace with local folder access, a Markdown-native WYSIWYG editor, tabs, outline navigation, image asset handling, and CLI automation. Success means users can open a local folder, find or create Markdown files, edit confidently, preserve unsaved work, and let local automation interact with the same workspace without losing trust in the file system state.

## Brand Personality

Calm, precise, local-first. The interface should feel like a capable desktop tool rather than a marketing product: quiet enough for long writing sessions, explicit about file operations, and dependable around destructive actions.

## Anti-references

Avoid decorative SaaS dashboards, marketing-style hero layouts, playful editor chrome, heavy gradients, glass panels, and modal-heavy flows. Avoid hiding file-system consequences behind vague labels. Avoid visual novelty that makes common editor actions harder to recognize.

## Design Principles

1. Preserve flow for writing and reviewing Markdown.
2. Make file-system consequences explicit before they happen.
3. Keep navigation dense, scan-friendly, and predictable.
4. Surface automation state without letting it dominate editing.
5. Prefer desktop conventions over invented affordances.

## Accessibility & Inclusion

Target WCAG 2.1 AA for contrast, focus visibility, keyboard access, and screen-reader labels. Reduced motion should be respected. The product should remain usable for color-blind users by pairing color with text or shape, especially for dirty states, warnings, disabled controls, and destructive actions.
